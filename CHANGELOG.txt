ROUTER HOME INSTALLER - CHANGELOG
=================================
Newest first. To get a newer version on your router: from 2.6 on, Control Center →
"Router Home updates" → Check (installs from GitHub in about a minute), or run the
installer again and choose 1. Your settings (Discord webhook, weather ZIP, NAS backup,
etc.) are kept either way.


VERSION 2.6.9  (2026-11-22)
-------------------------
  - The Security status chip at the top now includes Known vulnerabilities: it says
    "Security: update needed" (or exposed / infection signs) in orange or red instead of
    "Security OK" when the Security card finds something, and the "Everything is running
    smoothly" line mentions it too.
  - Clicking the Security chip now scrolls to the Home tab's own Security card (and
    outlines it) instead of opening GL's Security page.


VERSION 2.6.8  (2026-11-22)
-------------------------
  - After a GL firmware upgrade, the services you chose to turn off during install (app
    detection, cellular/SMS, Bonjour) can come back on. The alert now says so plainly
    ("The firmware upgrade turned 6 services back on", with the firmware versions) instead
    of "Security: Optimized services stay off failed", and its button "Turn them off
    again" only touches those services. Auto-heal can do it by itself next time (Settings
    > Auto-heal > "Turn a service off again if it comes back").
  - Fixed: "netifyd" was listed as turned back on after an upgrade although it stays off
    by its own setting. Thanks to the user who reported it.


VERSION 2.6.7  (2026-11-22)
-------------------------
  - Security card: no more red "failed" alerts for settings your router never had. If
    you kept GL's defaults (for example chose "Home tab only" in the installer), checks
    like "SSH key-only login" or "HTTPS-only admin panel" now show under "Recommended ·
    optional" with a short explanation and a "Turn on" button where one click is safe.
    A check only counts as failed if it passed on your router before. Thanks to the user
    who reported it.
  - "Restore settings" only puts back what your router had before, and never switches
    SSH to key-only unless an SSH key is installed (it could have locked you out of SSH).
    Router Home also no longer re-locks OpenVPN login files on routers where you didn't
    lock them yourself.
  - New in Settings: Temperature unit (°F or °C) for the whole Home tab, the weather and
    Discord alerts.
  - Weather works outside the US: enter a US ZIP code or a city ("London", "London, GB",
    "Toronto", "Paris, TX"). Weather can also be turned off completely (Settings >
    Weather > Show weather).


VERSION 2.6.6  (2026-11-22)
-------------------------
  - New GL.iNet security notices: the router also reads GL.iNet's own news feeds
    (Security Updates and the blog) once a day. A new security post that the
    vulnerability list doesn't cover yet shows on the Security card as "New notice, not
    checked yet" and sends a Discord alert the same day, so you never have to go looking.
    Once the signed list on GitHub is updated, the router checks itself for it.
  - Known vulnerabilities is now a featured panel at the top of the Security card: green
    "No known vulnerabilities" (with the model, firmware and how many notices/CVEs were
    checked), orange or red when something is found (it names what was found), blue for
    a new GL notice. Buttons: Review & fix (or Details) and Check now.
  - Windows installer fix: a successful install was reported as "The install didn't
    finish (code ... 0)", and the router's progress text didn't show while installing.
    The install itself was fine. It now shows the progress live and reports success
    correctly (same fix for Remove and Undo). Also gone: the harmless "Command failed:
    ubus call service delete ... (Not found)" line on a first install. Reported on a
    Slate 7 (GL-BE3600, firmware 4.11.0), which installs and runs fine.
  - Install instructions and both installers now remind you to turn on SSH first
    (Security > Access Control > Enable SSH) and explain that GL turns SSH off when the
    admin password is weak. Thanks to the user who suggested it.


VERSION 2.6.5  (2026-11-22)
-------------------------
  - Known vulnerabilities, on the Security card: checks the router against published
    security problems with plain rules (no AI). Two sources: GL.iNet security notices,
    turned into a signed list of checks on the Router Home GitHub page (security folder),
    and the National Vulnerability Database (published CVEs for your exact model and
    firmware). Shows Not affected / Exposed / Signs of infection / Firmware update needed,
    offers a one-click fix where one is safe (it asks first and keeps an undo script or an
    evidence copy), and sends a Discord alert (new type "Vulnerability"). Downloaded once a
    day; the checks on the router repeat every 10 minutes. First entry: GL's 2026-11-20
    notice (malware via cloud remote management): checks for GL's sign of infection and
    whether GoodCloud remote management is on.


VERSION 2.6.4  (2026-11-22)
-------------------------
  - New "Network" tab in the GL.inet Utilities Toolkit card:
    MTU check: measures the biggest packet your internet path (and the path to each VPN
    server) carries, and shows the best size for every WireGuard tunnel. Measuring changes
    nothing. "Use" changes a tunnel's size and tests it for a minute; if websites or
    full-size packets stop getting through, the old size comes back by itself.
    Speed limits: cap a device's download and upload speed (Mbps), using GL's own speed
    limiter (the same one as Clients > Speed limit), so limits stay after a restart.
  - Daily update check: each router asks GitHub once a day for a newer Router Home and
    sends one Discord message per new version (new alert type "New Router Home version";
    it never installs by itself).
  - Zram after firmware upgrades: a GL firmware upgrade removes the zram-swap package.
    Router Home now reinstalls it by itself once the internet is back (only on routers
    that had it) and sends an alert. The upgrade checklist mentions it.
  - Update button: a release tag typed with an extra dot ("v.2.6.4") no longer makes a
    good install roll back; the version number is read out of the tag.
  - Mac installer (contributed on GitHub, pull request #1): the password is asked only
    once (files are sent over the same connection as the install), stricter IP and menu
    checks, safer temp files that are always cleaned up, and the "forget the old router
    key" question only appears when that's really the problem.
  - Windows installer, the same improvements: the password is asked only once, the
    "forget the old router key" question only appears for a real key change, stricter IP
    check, helper files are always removed from the router. Also fixed: typing anything
    other than 1-4 at "Choose" used to go ahead with an install; it now asks again.


VERSION 2.6.3  (2026-11-22)
-------------------------
  - Network Health no longer counts one false "no answer" right after the router or
    Router Home restarts. The steady pings take a moment to send their first reply; that
    moment is now skipped instead of recorded as a missed check.


VERSION 2.6.2  (2026-11-22)
-------------------------
  - Access points (e.g. a Flint behind a main router) no longer show a false "!" on
    Internet in Network Health. An access point's internet check goes through the main
    router and its VPN; some VPN servers (Nord) briefly ignore a device that starts lots
    of new pings, which looked like "no answer". The check now keeps one steady ping per
    server running, like the VPN checks. Routers in normal router mode are unchanged.
  - Update button fixes: installing an update no longer takes the admin page offline
    for a few minutes (the installer reloads the web server instead of restarting it),
    and a failed update now rolls back within about a minute.


VERSION 2.6.1  (2026-11-22)
-------------------------
  - Update status on the home screen: under "Everything is running smoothly" the page
    now says "Router Home is up to date", or "Router Home needs an update" with an
    Update now button that opens the update window. Checked when the page opens (at
    most once an hour); it never installs by itself.


VERSION 2.6  (2026-11-22)
-------------------------
  - Updates from GitHub: Control Center → "Router Home updates" checks
    github.com/xDarkHawkx/RouterHome for a newer release, shows what's new and installs
    it in about a minute. Only updates signed with the Router Home release key install;
    a tampered download is refused. The current version is saved first and put back
    automatically if anything goes wrong ("Go back to it" restores it later). The page
    also checks once a day and shows a note; it never installs by itself.
  - Installer fix: on some routers the installer could stop silently partway through
    (it depended on the order files came out of the archive). Fixed.
  - New "GL.inet Utilities Toolkit" card at the bottom of the page: point-and-click
    tools inspired by phantasm22's GL.iNet Utilities Toolkit. Hardware and VPN crypto
    details, benchmarks (CPU stress, VPN & crypto speed, storage, memory, DNS latency),
    zram settings, a package system check, and SSH key management.
  - System card: a Zram gauge next to Memory shows how much of the router's compressed
    memory (zram) is in use, with the compression ratio on hover. It only appears when
    zram is on (GL's zram-swap package).
  - Network Health: the modem check works with the cable modem in bridge mode (it
    pings the modem itself instead of your ISP's gateway, which may ignore pings).
  - VPN outage log (VPN Health card, "Outage log"): every real VPN outage of the last
    7, 30 or 60 days, with how long it lasted, why, and where your devices went. Filter
    by provider and copy it or send it to Discord for your VPN provider's support.
  - More accurate VPN checks: each tunnel now keeps one steady ping running (like
    "ping -t" on a PC) instead of starting new pings every check. Some VPN servers
    (Nord, Surfshark) pause answers to lots of new pings, which showed up as false
    30-second "stalls" while your devices were fine. Ping-only blips no longer count
    in the 7-day reliability numbers or the 5-hour monitor.


VERSION 2.5  (2026-11-14, updated 2026-11-18)
-------------------------
  - Phone view: the 📱 button (automatic on small screens) shows a compact page with
    big buttons: status, internet, VPN switches, devices, speed test, clear alerts...
  - Outage & lag log (ISP report card): every outage with its likely cause, lag
    episode, modem restart and slow speed test of the last 30 days, ready to copy or
    send to Discord for your ISP.
  - Alerts when your internet is slower most evenings, and when the cable modem
    restarts by itself. Opt-in alert when one device suddenly has far more blocked
    lookups than usual.
  - Auto-heal: after giving up on a tunnel, the router keeps watching its VPN server
    and reconnects as soon as it's back.
  - Network Health card: busiest device right now, DNS speed vs usual (and AdGuard's
    blocked share), ping under load from normal heavy use, connection table, IPv6
    status, the likely cause of the last outage, and a Good / Fair / Poor grade per
    VPN tunnel.
  - New repairs/alerts: modem switched into router mode (double NAT) and back; slow
    DNS (AdGuard vs its provider); a tunnel stuck "connecting" gets restarted; a
    service whose memory keeps growing gets restarted; and an opt-in SQM trial for
    lag under load (two warnings first; it undoes itself if it doesn't help).
  - The leak test no longer warns about DNS when AdGuard sends its lookups encrypted.
  - Alerts: Mute (1 hour / rest of today / a week), "Clear all" under the alert
    banners, show or clear Recent events by type, choose how long events are kept,
    and a daily digest for less urgent alert types.
  - VPNs you remove are forgotten from the speed history and reliability after 24
    hours (or right away with "Forget removed VPNs"); remove single lines with ×.
  - Network Health card: internet health at a glance. A Good / Fair / Poor verdict,
    where a problem is (router -> modem -> internet), a warning when the modem is in
    router mode (double NAT), jitter and lag spikes, what the line is good for right
    now (browsing, calls, gaming), uptime and the last outage, a 24-hour strip, and
    the cable modem signal.
  - New Discord alert: high internet ping (default over 75 ms; set it in the alert
    settings). Catches both steady high ping and frequent lag spikes, and is built
    not to spam: at most one alert an hour, one reminder after 2 hours, one "back to
    normal". A Home page banner shows while it's high.
  - Internet card: new "WAN ping" section. Cloudflare, Google and Quad9 are pinged
    directly over your internet connection every 10 seconds, with a graph (Last hour /
    24 hours, with a ms scale, times and hover values) and per-server averages
    (10 min / 1 h / 24 h), jitter, packet loss and range.
  - Speed Test card: "Test VPN" now asks which tunnel to test: one of them, or all of
    them one after another. Testing one tunnel keeps the others' earlier results.
  - OpenVPN tunnels now get everything WireGuard tunnels get: VPN Health checklist,
    Network Health row, speed test, alerts, failover (WireGuard and OpenVPN tunnels
    can cover for each other), auto-heal, the 5-hour monitor, the leak test, the DNS
    Race and the server picker on the VPN card. OpenVPN has no "handshake", so its
    stand-in is "Server responding": when data last came back from the VPN server.
  - Your OpenVPN provider login (saved by GL readable to every program on the router)
    is now kept root-only, like the WireGuard key file, and re-locked automatically
    after you save VPN settings. The Security card shows "OpenVPN login files locked".
  - New "VPN Health" card next to VPN: for each tunnel, pings (Cloudflare and Quad9),
    a domain lookup and a web page check through the tunnel, the handshake, and drops
    in the last hour / 24 hours. Hidden in access point mode.
  - VPN tunnels you turn off, remove or switch to another server no longer cause
    "VPN down" alerts or a stuck warning: they're dropped from the checks (or start
    fresh), and a tunnel gets 2 minutes to reconnect after a change. New tunnels are
    picked up right away.
  - Easter egg: a red "DNS" button at the end of the dock opens "It's always DNS, Hub":
    every DNS setting of your network in one place, how a lookup travels, who answers
    your devices, a DNS Race between all your DNS servers, and a Lookup map that shows
    every step it takes to find a name (e.g. weather.com: AdGuard -> Quad9 -> root ->
    .com -> the site's own servers).
  - Packet-loss alerts at the top of the page have a "Clear" button: it restarts the
    10-minute loss check from scratch (unlike Dismiss, which only hides it for 24 h).
    Changing or removing a VPN tunnel clears its loss history automatically too.
  - VPN Health card: a "Clear all VPN alerts" button (clears every VPN warning, moves
    devices back to their own tunnels, and re-checks every tunnel from scratch).
  - VPN Health card: a "Monitor 5 h" button. It watches every VPN tunnel closely for 5
    hours (pings every few seconds, plus a domain lookup and a web page through each
    tunnel) and sends one summary to Discord at the end. While it runs, the button
    counts down; click it to stop early (the summary is still sent).
  - Internet card: "DNS" is now "WAN DNS", with a new "LAN DNS" row under it (the
    DNS your devices are told to use, e.g. AdGuard on a NAS).
  - VPN failover and "tunnel down" alerts now need pings AND a web page through the
    tunnel to fail. If only pings stop (some VPN servers briefly ignore pings while
    traffic keeps flowing), devices stay put; VPN Health lists these as "ping-only
    blips". Real outages still switch tunnels in about 30 seconds.
  - VPN card: an on/off switch on each tunnel, and click a tunnel to switch it to
    another server you've saved in GL's VPN page.
  - Card order: Security now sits next to AdGuard Home; Clients and Top Devices by
    Data sit side by side. Top Devices shows 4 devices per list and scrolls for more.
  - Small colored icons next to the card titles (System, Network Health, Last 24
    Hours, Ads Blocked, Data This Month, Clients, Top Devices, Speed Test & Leak Test,
    Speed History, Sensors, Services).
  - Control Center: a "Restart modem" button under Back up settings and Restart
    router. It asks first, and only appears in router mode once the cable modem is
    connected (Settings > Cable modem).
  - Internet card: "Modem uptime" under Cable modem signal (how long since the cable
    modem last restarted; read hourly with the signal).
  - Top bar: an "All systems normal" status light (orange "1 warning" / red "1 problem"
    when something needs attention; click it to jump to the alerts). Green lights,
    including Online, blink slowly.
  - New auto-heal repairs (Settings > Auto-heal):
      * Retry a failed NAS backup (after 1 hour, then 6 hours).
      * Wake the NAS with Wake-on-LAN if it's asleep (when it goes offline, and
        before a backup).
      * Fix a VPN leak the hourly leak test finds, then test again.
      * Clear a runaway device's connections before the connection table fills up.
      * Clean up router storage when it's nearly full.
      * Access points: reconnect to the main router if the link stops working.
      * Opt-in: turn a service off again if a firmware update restarts it.
      * Opt-in: switch to a quieter Wi-Fi channel (switches back if devices don't
        reconnect).
      * Opt-in, last resort: restart the cable modem after 15 minutes without
        internet. Two warnings before you can turn it on, and a 5-minute "Cancel
        restart" banner on the Home tab before it acts.
  - Auto-heal has its own window: Settings > Alerts & backups > Auto-heal (it was
    inside Discord alerts). Your switches are kept, and you still get a Discord
    message when a fix runs.
  - Cable modem: fixed reading the Xfinity XB10's signal page (channels and SNR were
    missed). The Internet card now says "Cable modem signal" with the status, SNR and
    channel count; click it for every reading (model, lock status, power, errors).
  - Live wallpaper: the background colors slowly move and blend (macOS and Android
    looks, matching your accent color / color theme). Switch: Settings > Live
    wallpaper.
  - Control Center is shorter: the switches, Back up settings and Restart router
    stay; privacy mode, look, colors, layout, Discord alerts, NAS backup, cable
    modem, ISP report card and weather moved into one "Settings" window.
    It has its own search box, and the page search bar (/) finds settings too.
  - New trackers and repairs:
      * Tailscale key expiry warning (14, 7 and 1 days before).
      * "Alert me if it goes offline" switch in each device's sheet (your NAS is
        pre-selected on main routers).
      * Cable modem signal check (Xfinity gateways: enter the gateway password once in
        Control Center > Settings > Cable modem).
      * Weekly Wi-Fi report now includes weak-signal devices, devices dropped for a poor
        connection, connect/drop counts and radar events (and the channel suggestion
        is fixed).
      * Clear "NAS is full" message when a backup fails for lack of space.
      * Wi-Fi band self-heal: a band that stops working is restarted once.
      * A slow nightly speed test is re-tested once before it counts.
      * A stalling VPN server gets a suggestion; optional auto-switch to the next
        server on that tunnel (off by default).
      * Monthly summary on Discord on the 1st (with a Preview button).
  - Leak test results fold into one line ("No leaks found · N checks passed"); click
    the arrow for the full list. It opens by itself if anything fails.
  - The VPN Reliability card is now part of the VPN card: each tunnel shows its last
    7 days (uptime, ping, loss, day/evening ping, nightly speed) right under it.
  - VPN tunnels and the internet connection are now checked against two servers at
    once (Cloudflare and Quad9); they only count as down when both get no answer.
  - Routers in access-point mode no longer send "Internet outage" alerts (the main
    router reports real outages). In router mode they alert as before.
  - Recent events window: Clear the past hour, day, week, or all events.
  - Travel routers (Slate, Beryl, etc., or any router getting internet over Wi-Fi or a
    phone): hotel sign-in page detection with an "Open sign-in page" button; a
    "This Network" safety check each time you join a network; "Networks You've Used"
    report cards with grades; a home check through Tailscale; and data per network with
    an optional daily limit. Home routers on a cable aren't affected.
  - Touchscreen weather: all text is now white with a soft shadow, easier to read on
    the radar map.
  - A speed test on one of your own GL.iNet routers (access point / repeater) no longer
    sets off the "Unusual upload" alert. Steady uploading from them still does.
  - Quad9's other networks (shown as "WOODYNET-2" etc.) are now named Quad9 in the DNS
    check.
  - LED on/off (e.g. an LED schedule) no longer sends "Router settings changed".


VERSION 2.4.1  (2026-11-11)
---------------------------
  - Page search: a search box under the top bar finds anything on the Home tab (a
    device, "tunnel 2", "temperature"...) and jumps to it. Press / to start typing.
  - Search box at the top of Control Center > Discord alerts: type "vpn", "upload",
    "auto fix", "reboot"... to find any alert type, schedule or auto-fix switch.
  - Automatic leak test every hour (main routers), with a "Possible VPN / DNS leak"
    alert if anything fails and a message when it's clear again.
  - The status chips at the top always fit on one line (they shrink, then use short
    labels like "VPN 3/3"; hover for the full text).
  - VPN & DNS leak test, in its own box in the renamed "Speed Test & Leak Test" card:
    proves each tunnel hides your home address, devices can only leave through the VPN,
    the kill switch is armed, IPv6 can't bypass it and DNS goes through it. The DNS
    check also names the company answering your lookups (Quad9, Cloudflare, ... or your
    ISP = leak) and works with the VPN off. Read-only, ~30 s.
  - Hourly DNS check: which DNS provider answers your lookups, with history; alerts if
    your ISP starts answering or a never-seen provider appears.
  - NAS backups are now restore-checked after every backup (the newest copy is
    downloaded back into memory and checked to be complete), with a "Backups healthy"
    chip at the top and "Verify now" in the NAS backup settings.
  - Alert when a router restarts unexpectedly (power cut or crash).
  - New "Recent events" line in the System card ("No events" or the number). Click it
    for a timeline of everything the router noticed or did (outages, VPN failovers and
    auto-fixes, new devices, sign-ins, settings changes...), newest first, click an event
    for details. Works even without Discord; kept for 14 days.
  - New alert "Unusual upload from a device": a device sending 1 GB+ in about an hour
    and 10x more than it normally does (possible hacked device, malware or a runaway
    backup). Turn it on/off in Control Center > Discord alerts.
  - New "About" in the top bar (next to System): a searchable guide to every feature
    (what it does and how to use it), grouped by area. The footer now reads
    "Router Home v2.4.1 · build ... · Made by DogZoomZoom & Claude AI (the bot)".
  - More self-care (each with a switch in Control Center > Alerts where it changes
    something, and a Discord message when it acts):
      * VPN tunnels that stay down are disconnected and reconnected after 2 minutes
        (was 5), and you're told if 3 tries didn't help and where their devices are.
      * Internet renew when the modem cable is up but there's no internet for 3 min.
      * The router's own DNS is restarted if it stops answering (never touches AdGuard).
      * Tailscale is restarted if it's on but stays disconnected for 10 minutes.
      * Alerts: a turned-off service running again, the DHCP pool 90% full, and the
        router log flooding (300+ lines a minute).
  - System card: new "DHCP pool" gauge: how many of the router's DHCP addresses are in
    use (e.g. 28 of 150), turning orange/red as the pool fills. Hover for the address
    range. Only shown when the router hands out addresses (not in access-point mode).
  - Travel routers (e.g. Slate 7 Pro): new "Wi-Fi Uplink" card next to Internet (the VPN
    card moves further down). It shows the network the router is linked to, signal
    strength with bars, band, Wi-Fi generation, security, link speed, retries, IP,
    gateway, DNS, MAC and how long it's been connected. "Choose network" lists your
    saved networks (one tap, no password) and nearby networks from a scan, or joins a
    hidden one. Business (802.1X) networks are sent to GL's Internet page.
  - Access points: the Tailscale chip shows Tailscale's status too, but GL itself does
    not allow Tailscale in access-point mode, so it stays off there.
  - Removed the Network Map card (it wasn't needed). Its optional router-to-router
    pairing is gone too: it made the access point log an SSH sign-in every minute,
    which set off sign-in alerts. Saved layouts adjust by themselves.

VERSION 1.7  (2026-11-10)

Home tab
  - Smarter VPN health check: once a minute each WireGuard tunnel is also tested with a
    real web (HTTPS) request, in the background. A tunnel that still answers pings but
    can't load web pages now counts as down, so alerts, auto-heal and failover react to
    it (after about 2 minutes). Busy tunnels during a speed test don't count as failures.
  - Access point mode: the "slow internet" alert is skipped. An access point's own speed
    test goes through the main router, so it can't measure your internet plan.
    Tip: turn off the nightly speed test on access points (Control Center > Alerts).

VERSION 1.5  (2026-11-07)
-------------------------
Home tab
  - VPN failover now works on every model, not just the Brume 3. If one WireGuard VPN
    tunnel stops working for about 30 seconds, its devices move to another working
    tunnel and move back once it recovers. They never leave the VPN. This needs two or
    more tunnels. Turn it off in Control Center > Alerts > "Move devices to a working
    tunnel".

Installer: three new optional questions (each off unless you say yes)
  - Harden a few kernel security settings.
  - Check signatures on add-on packages (skipped automatically if the router can't
    verify GL's package lists).
  - Remove an unused FTP entry that some GL firmware ships.


VERSION 1.4  (2026-11-07)
-------------------------
Home tab: the router now looks after itself
  - Automatic reboot ONLY for serious problems that last: memory nearly exhausted,
    connection table full, or the admin services stuck. A gentler fix is tried first.
    It reboots at most once a day and twice a week, never within 6 hours of starting,
    and never during a speed test, backup or upgrade. Problems that aren't urgent wait
    for 2-5 AM. You get a Discord message before and after. Switch:
    "Reboot the router if it has a major problem".
  - Restarts the router's admin/API services if they stop answering.
  - Clock check: fixes and alerts if the router's time stops syncing.
  - Alerts when the connection table, storage, RAM disk or memory gets nearly full.
  - Settings change log: an hourly Discord message listing any router settings that
    changed. Passwords and keys are never shown.
  - Slow-internet alert: when 3 nightly speed tests in a row are under 70% of your plan.
  - Cable check: alerts if the cable to your modem (or to the main router, in access
    point mode) drops below its normal speed, or keeps disconnecting.
  - Weekly Wi-Fi channel report (routers with Wi-Fi): Sunday 3 AM. Says whether a
    clearly quieter channel is available. Switch: "Weekly Wi-Fi channel report".
  - New alert types you can turn on/off: Router health, Settings changed,
    Slow internet, Wi-Fi report.
